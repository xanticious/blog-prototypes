You do not need a special writing program to keep a book blog. You need a place to put sentences, and a way to say “this line is a heading” without the file becoming a private format that only one website understands. Markdown is that way. It is a text file. The marks are typed with keys you already have.

*Alice’s Adventures in Wonderland* is a useful companion here, not because Carroll used Markdown, but because the book trusts plain language to do strange work. A heading is still a heading. A list is still a list. The costume can wait.

## What the marks look like

A Markdown file is the words, plus a few symbols that mean “format this.”

```markdown
## A small heading

This is a paragraph. *This is italic.* **This is bold.**

> This is a quotation.

- a list
- of things you noticed
```

That is most of what a book review needs. Two asterisks for bold, one for italic, a `>` for a line you are quoting, a `#` or two for a heading, a hyphen for a list. You can learn them in an afternoon and then forget you learned them, the way you forget you know how to indent a paragraph.

If the website disappears, the file is still readable. Open it in any program that shows letters. The symbols are a little ugly and completely honest.

## Tools that stay out of the way

Pick one. You do not need a collection.

- **The notes app you already open.** If it can export or copy as plain text, it is enough to draft in. When you are ready, paste the draft into a file that ends in `.md`. The ending is a hint to people and programs: this is Markdown.
- **A writing editor with a preview.** [iA Writer](https://ia.net/writer), [Typora](https://typora.io/), and [MarkText](https://github.com/marktext/marktext) show the formatted page beside, or instead of, the symbols. They feel closer to a sheet of paper than to a control panel. Typora hides the marks while you type, which some people love and some people find slippery.
- **A folder of text files.** [Obsidian](https://obsidian.md/) keeps a pile of Markdown notes on your computer and lets you link one note to another. It is a good home for a reading journal. You can ignore the plugins.
- **A programmer’s editor, used gently.** Visual Studio Code, Cursor, and similar programs open a Markdown file, show a preview, and let you save. If a friend who builds the site already lives in one of these, write there too. You are not required to understand the rest of the window.
- **Nothing installed.** [Dillinger](https://dillinger.io/) and other browser editors let you type on the left and see the page on the right. Fine for a first experiment. Copy the text out before you close the tab. A browser tab is not a filing cabinet.

TextEdit on a Mac, set to plain text, and Notepad on Windows will also do. They will not preview anything. That is all right. The marks are few enough to check by eye.

## What not to worry about

Tables, footnotes, and embedded videos can wait. A review is paragraphs. If a tool’s website leads with themes, publishing, collaboration, and a monthly fee, you can leave it for later. The writing does not need an account.

You also do not have to make the file look like the finished website. On this blog, the site reads the Markdown and sets the type. Your job in the file is the words and the small marks. The clay-colored page is someone else’s job, already done.

## A ten-minute practice

Open a new file. Write the title of a book on the first line, with `##` and a space in front of it. Under that, write four sentences about a scene you remember. Put one sentence you are quoting on its own line, with `>` in front of it. Save the file with a name like `notes.md`.

If you can read it tomorrow without the website, you have the tool you need. Everything else is furniture.
